# Архитектура

## Предложенный стек

**C# + WPF, поддерживаемая LTS-версия .NET на момент реализации.** Выбор конкретного SDK закрепить в `global.json` после проверки актуальной поддержки. WPF подходит для Windows-виджета, трея и drag-and-drop. Excel не запускается.

Сначала проверить на целевых Windows механизм уведомлений и установку: этот интеграционный риск нельзя откладывать до конца. Точную матрицу поддерживаемых ОС зафиксировать до публичного релиза; отдельно проверить Windows 11 и, если заявлена, Windows 10.

## Модули и границы

| Модуль | Ответственность |
| --- | --- |
| Core | Календарный цикл, пять рабочих дат, соответствие день–номер меню, имена результатов |
| Xlsx | Проверка XLSX, чтение выбранной даты, точечная замена и проверка сохранения |
| Application | Импорт комплекта и атомарный экспорт, координация сервисов |
| Storage | Локальные настройки, внутренние копии шаблонов, безопасная запись и миграции |
| Notifications | Расписание, обработка пропущенного события, snooze, защита от дублей |
| WPF UI | Виджет, трей, настройки, drag-and-drop, доступные пользователю ошибки |
| Packaging | Установка, удаление, ярлыки, self-contained сборка и релиз |

Не связывать календарное ядро с WPF или реальными системными часами. Передавать время через интерфейс часов для воспроизводимых тестов.

## Ключевые модели и контракты

- `CycleSettings`: опорный понедельник меню 1–5, состояние завершённой настройки.
- `MenuSet`: комплект 1–5 либо 6–10; пять записей `MenuTemplate`.
- `MenuTemplate`: день недели, внутренний путь, исходное имя, лист и ячейка даты.
- `ExportRequest`: целевой понедельник, выбранный комплект, каталог назначения.
- `ExportPreview`: пять строк с номерами меню, датами и будущими именами.
- `ReminderSettings`: enabled, локальное время воскресенья, задержка повторного напоминания.
- `ReminderState`: последнее обработанное воскресенье и отложенное событие.

Сервисы: `ICycleService`, `ITemplateStore`, `IXlsxDateEditor`, `IExportService`, `IReminderScheduler`, `IClock`. Точные сигнатуры определяет первый этап реализации; модульным агентам согласовать их перед параллельной работой.

## Сохранность XLSX

Предпочтение точечному изменению Open XML внутри ZIP-контейнера, например с Open XML SDK, а не пересозданию всей книги библиотекой таблиц. Выбор библиотеки подтвердить экспериментом сохранности.

На локальном прототипе пересохранение универсальной библиотекой удаляло часть настроек печати. Поэтому обязательны сравнение частей архива и семантическая проверка всех изменённых XML. Это наблюдение из прототипа, не утверждение о любой библиотеке.

- Разрешать лист через `workbook.xml` и relationships, не полагаться на постоянный `sheet1.xml`.
- Учитывать системы дат 1900/1904; проверить преобразование Excel serial.
- Формат даты менять локально: если стиль используется другими ячейками, клонировать стиль, не менять общий формат книги.
- Если выбранная ячейка содержит формулу или не поддерживается, остановиться с объяснением; не уничтожать формулу молча.
- Датировать только подтверждённую ячейку. Множественные даты не заменять глобальным поиском.
- Зашифрованные или повреждённые документы объяснимо отклонять. Не обходить защиту незаметно.
- Валидировать ZIP/OOXML, ограничивать ресурсы при чтении; временные пути не должны выходить за рабочий каталог экспорта.

## Локальные данные

Предлагаемое размещение: `%LocalAppData%/MenuWidget/` с настройками JSON, шаблонами обоих комплектов и техническим состоянием напоминаний. Каталог готовых файлов выбирает пользователь.

Сохранение настроек и замена комплекта — транзакционно через временную запись. Не хранить абсолютные пути разработчика как значения по умолчанию. Ограничить журналы, не копировать содержимое меню в логи.

## Уведомления и жизненный цикл

План: системное пользовательское задание на воскресенье и запуск приложения в специальном режиме напоминания. При входе в Windows выполнять проверку последнего пропущенного события. Конкретную регистрацию системных уведомлений согласовать с выбранным типом установщика и проверить на чистой машине.

Режим напоминания показывает уведомление без открытия основного окна; нажатие открывает существующий экземпляр или запускает его. Несколько процессов должны согласовывать событие атомарно, например через mutex и состояние. Повтор через 30 минут должен сохраняться после выхода из UI. При отключении и удалении программы убирать связанные задания.

Автозапуск виджета и системное расписание напоминаний — независимые настройки. Выключенный компьютер не будить по умолчанию. Не использовать сервер или Codex-автоматизации как зависимость пользовательского продукта.

## Обновления

В v1 обновление через загрузку установщика с GitHub Releases. Автоустановка обновлений не входит. Схема настроек версионируется; миграции сохраняют данные и имеют тесты.
