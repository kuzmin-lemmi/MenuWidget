# Требования к продукту

## 1. Назначение и аудитория

Программа для сотрудников, которые публикуют школьное питание на сайте. Основная подготовка происходит по выходным. Пользователь не обязан разбираться в Excel, номерах ячеек, файловых форматах и настройках Windows.

Исходный цикл: десять рабочих меню, первая календарная неделя — № 1–5, вторая — № 6–10, затем повторение. По подтверждению заказчика цикл продолжается по календарю, включая праздники и каникулы. Производственный календарь не нужен.

## 2. Основной поток

1. Открыть программу через ярлык или значок рядом с часами.
2. Явно выбрать комплект «Меню 1–5» / «Меню 6–10».
3. Перетащить пять файлов в область загрузки либо выбрать файлы диалогом.
4. Увидеть пять строк: день недели, исходный файл, номер меню, новая дата, будущее имя.
5. Исправить порядок, если автоматическое определение по именам ошибочно или невозможно.
6. Выбрать понедельник целевой недели.
7. Нажать «Подготовить 5 файлов».
8. Получить подтверждение и открыть папку с пятью результатами для самостоятельной загрузки на сайт.

Сохранять оба комплекта как шаблоны. Замена одного комплекта не затрагивает другой. Импорт сначала проверяется, затем целиком заменяет выбранный комплект; ошибка не должна уничтожать старые шаблоны.

## 3. Настольный виджет

Это компактное отдельное окно Windows, а не панель Windows Widgets и не веб-страница.

- Русский интерфейс; разумный размер, поддержка масштабирования экрана.
- Перемещение мышью, сохранение позиции с восстановлением в видимой области экрана.
- По желанию: закрепление поверх других окон и запуск при входе в Windows.
- Значок в системном трее: открыть, подготовить меню, настройки, выйти.
- Закрытие окна скрывает виджет; явное «Выйти» завершает приложение. Объяснить поведение при первом использовании.
- Текущая дата, день недели и номер меню по настроенному циклу.
- В выходные — надпись о выходном и ближайшая рабочая неделя с комплектом.
- Наглядное состояние каждого комплекта: не загружен / готов / требует исправления.
- Переключатель комплекта, drag-and-drop, альтернативный выбор файлов, предпросмотр пяти дней, кнопка подготовки и настройки.

## 4. Даты и цикл

- Пользователь задаёт понедельник, соответствующий комплекту 1–5. Это опорная дата.
- Чередование определяется разницей календарных недель относительно опорной даты; корректно обрабатывать недели до неё и переход года.
- В субботу и воскресенье предлагать следующий понедельник, в будни — понедельник текущей недели. Можно выбрать другую неделю.
- Предлагать комплект по циклу, разрешать явный ручной выбор. Ручной выбор на один экспорт не сдвигает опорную дату.
- При первом запуске цикл считается ненастроенным до выбора опорной даты; не показывать уверенный номер сегодняшнего меню без настройки.
- Дата и расписание используют локальный часовой пояс пользователя.

Пример из реальной задачи: комплект файлов 05–09.10.2026 соответствует меню 6–10 и повторяется 19–23.10.2026. Для проверки можно использовать опорную дату 12.10.2026 для меню 1–5. Это пример, не глобальная настройка для всех пользователей.

## 5. Входные и выходные файлы

- Первый релиз поддерживает `.xlsx`; другие форматы объяснимо отклоняются.
- Комплект содержит ровно пять разных файлов. Неполную загрузку можно показать в интерфейсе, экспорт недоступен до заполнения всех дней.
- Не импортировать служебные файлы блокировки и временные файлы Excel/LibreOffice.
- Если имена содержат даты, предложить сортировку по ним; до сохранения показать привязку к дням. Для произвольных имён дать ручное распределение.
- Известный шаблон: надпись «День» в I1, дата в J1 первого листа. Другие шаблоны: выбор листа и адреса ячейки для каждого файла, с отображением текущего значения. Общую настройку можно применить ко всем пяти, но проверить каждый.
- Менять значение даты, сохраняя тип Excel date и отображение `dd.MM.yyyy`.
- Не менять блюда, граммовки, прочие даты, формулы, рисунки, структуру листов, стили и параметры печати.
- Имена результатов: `YYYY-MM-DD-sm.xlsx`. Пример: `2026-10-19-sm.xlsx`, внутри дата `19.10.2026`.
- Выход — отдельный каталог для выбранной недели. Повторный экспорт создаёт новый каталог, а не молча заменяет ранее подготовленные файлы.
- Сначала сформировать и проверить весь комплект во временном каталоге. Публиковать результат только при успехе всех пяти файлов. При ошибке убрать временные результаты и дать понятную причину.
- Исходники и внутренние шаблоны не перезаписывать экспортом.

## 6. Напоминания

- Пользователь сам включает напоминание и задаёт время в воскресенье; пример времени — 18:00, не скрытая обязательная настройка.
- Время можно изменить; напоминания можно отключить. Не создавать задания без включения функции пользователем.
- Текст: «Пора подготовить файлы питания на 19–23 октября» с корректным диапазоном следующей недели.
- Действия: открыть программу, напомнить позже (например, через 30 минут).
- Окно программы может быть закрыто; расписание должно продолжать работать.
- Если компьютер был выключен, после следующего входа показать одно последнее пропущенное напоминание, не всю очередь.
- Не дублировать уведомление при повторном запуске приложения, одновременной работе фонового запуска и виджета, изменении времени или перезагрузке.
- При изменении расписания обновлять прежнее задание. При отключении удалять его и отложенное напоминание.
- Системные настройки уведомлений и «Не беспокоить» имеют приоритет. В настройках предусмотреть «Проверить уведомление» и понятную диагностику.
- Сохранять еженедельное напоминание независимо от прошлого экспорта: подготовка файлов не подтверждает загрузку на сайт.

## 7. Установка и данные

- Обычный установщик, ярлык на рабочем столе, запуск без командной строки.
- Не требуются установленный Excel, Python или .NET SDK. Поставлять необходимый runtime вместе с приложением.
- Настройки, шаблоны и расписание сохраняются между запусками; данные живут в профиле пользователя.
- Работа с меню без интернета и без регистрации.
- Удаление приложения убирает задания напоминаний и автозапуск. Пользовательские готовые файлы не удаляются.
- Обновление сохраняет комплекты и настройки.

## 8. Проверка и установка обновлений

- В настройках или меню виджета есть заметная кнопка «Проверить обновления» и номер установленной версии.
- По нажатию проверить стабильные опубликованные релизы `kuzmin-lemmi/MenuWidget` на GitHub. Черновики и prerelease не предлагать обычным пользователям.
- Если новее ничего нет: «У вас установлена последняя версия». Если релизов ещё нет: отдельное понятное сообщение. Сетевой сбой не трактовать как отсутствие обновлений.
- Если версия новее: показать установленную и доступную версии, описание изменений, кнопки «Установить» и «Позже».
- По «Установить» скачать совместимый установщик из релиза с прогрессом и возможностью отмены скачивания. Не требовать вручную искать или запускать файл в браузере.
- До запуска проверить целостность, допустимый источник и соответствие версии/архитектуры. При отсутствии подходящего или проверяемого артефакта остановиться с объяснением.
- Не начинать установку во время импорта/экспорта: предложить закончить текущую операцию. Сохранить настройки, затем передать управление установщику и корректно завершить приложение.
- После успешного обновления дать возможность открыть новую версию. Сохраняются оба комплекта, цикл, расписание, каталог результатов и настройки виджета; готовые меню остаются нетронутыми.
- Отмена, ошибка скачивания, отказ в повышении прав или неудачная установка не должны удалять данные и оставлять пользователя без рабочей версии. Установщик должен поддерживать безопасное обновление и откат неудачной установки.
- Проверка запускается по кнопке; скрытая фоновая установка и принудительное обновление не входят в первый релиз.

## 9. Вне первого релиза

Автозагрузка на сайт, облако, аккаунты, сбор телеметрии, редактирование питания, другие форматы документов, другие ОС, фоновая установка обновлений без действия пользователя. Изменение этих границ требует отдельного решения.
