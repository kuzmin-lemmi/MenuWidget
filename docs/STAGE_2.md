# Рабочая тестовая версия: импорт и экспорт меню

Внешний вид согласован пользователем. Реализован основной сценарий подготовки пяти файлов; сохранение комплектов и настроек подключено к интерфейсу. Это ещё не публичный релиз с установщиком.

## Что работает

- Выбор комплекта № 1–5 или № 6–10.
- Перетаскивание либо выбор `.xlsx`. Можно сначала добавить часть комплекта, затем остальные файлы.
- Окно подтверждения пяти дней: изменение порядка стрелками, выбор листа и адреса ячейки даты для каждого меню, просмотр текущей даты.
- Сохранение двух независимых комплектов во внутренних копиях. Исходные файлы впоследствии не нужны для экспорта, их содержимое не изменяется.
- Выбор рабочей недели, автоматическое предложение по календарному циклу и ручной выбор комплекта.
- Создание пяти файлов с именами `YYYY-MM-DD-sm.xlsx` и новыми Excel-датами в формате `dd.MM.yyyy`.
- Сохранение оформления и содержимого вне выбранной ячейки и её локального формата. Поддержаны системы дат 1900/1904; формула вместо даты объяснимо отклоняется.
- Публикация результата только после успешного создания всех пяти файлов. Повторный экспорт создаёт отдельную папку.
- Сохранение опорного понедельника, выбранной папки результатов, времени будущего напоминания и режима «поверх окон» между запусками.

## Запуск

На компьютере разработки: файл «Запустить MenuWidget.cmd» в родительской папке проекта либо `artifacts/app/MenuWidget.exe`. Автономной сборке не нужен установленный .NET или Excel.

Для вашего комплекта 6–10: в настройках укажите понедельник **12.10.2026** для начала цикла 1–5, сохраните, выберите комплект **6–10**, добавьте пять файлов и подтвердите порядок. На неделю с 19.10.2026 будут подготовлены меню 6–10. Эти даты служат примером, программа не привязана к ним.

По умолчанию результаты сохраняются в папку «Меню для сайта» внутри «Документы». Папку можно изменить в настройках. После подготовки открывается созданный каталог.

## Проверки

22 проверки проходят на синтетических документах и изолированном профиле:

- 9 календарных сценариев;
- сохранность XLSX при системах дат 1900/1904;
- защита от перезаписи исходника, перезаписи готового файла, формулы вместо даты и отсутствующей ячейки;
- восстановление настроек новым экземпляром хранилища;
- импорт внутренних копий, независимость двух комплектов;
- сохранение старого комплекта при ошибке замены пятого файла;
- пять правильных дат и имён после экспорта;
- сохранение прежнего результата при повторном экспорте;
- отсутствие частичного комплекта при повреждении пятого шаблона.

Проверки сохранности из этапа 1 теперь вызывают рабочий редактор `MenuWidget.Services/XlsxDateEditor`, а не отдельную копию экспериментального алгоритма.

Проверенная команда разработчика:

```powershell
./scripts/Build.ps1 -PublishApp
```

Настоящие школьные меню и личный профиль в автоматических проверках не используются. Продолжительные проверки установщиков и управление рабочим столом не повторяются: ручная приёмка интерфейса передана пользователю по его просьбе.

## Следующие функции

Системное воскресное расписание, трей и автозапуск, установка обновлений из GitHub и пользовательский установщик пока не подключены к рабочему приложению. Их элементы явно обозначены как недоступные. Отдельный экспериментальный MSI-стенд хранится в `experiments/MenuWidget.WindowsProbe`; он не является пользовательским приложением.

## Данные

Профиль приложения находится в `%LocalAppData%/MenuWidget`. Замена комплекта сначала полностью проверяет новые внутренние копии, затем атомарно меняет указатель на комплект. Предыдущие поколения пока сохраняются для восстановления; автоматическая очистка не выполняется.
